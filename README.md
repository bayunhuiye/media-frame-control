# 媒体逐帧控制

**简体中文** ｜ [English](README.en.md)

> **作者**：bayunhuiye ｜ **版本**：1.0.0 ｜ **最低 Obsidian 版本**：1.4.0

给 Obsidian 补上两件它原生没做好的事：

1. **GIF 逐帧查看** —— 点击 GIF 后出现「上一帧 / 播放暂停 / 下一帧」和帧号
2. **视频倍速** —— 视频下方有 0.1x–3.0x 倍速选择器，点击视频本体即可选中

## 安装

### 方式一：手动安装

把整个 `media-frame-control` 文件夹放到：

```
<你的库>/.obsidian/plugins/media-frame-control/
```

然后在 Obsidian 里：设置 → 第三方插件 → 关闭安全模式 → 在「已安装插件」里启用「媒体逐帧控制」。

重启 Obsidian 后如果没看到，再重启一次（插件注册需要重新扫描目录）。

### 方式二：从 GitHub 下载

从仓库下载 `main.js`、`manifest.json`、`styles.css` 三个文件，放进 `<你的库>/.obsidian/plugins/media-frame-control/` 再启用。

### 方式三：BRAT 安装

先装 [BRAT](https://github.com/TfTHacker/obsidian42-brat)，然后在 BRAT 设置里 Add Beta plugin，填 `bayunhuiye/media-frame-control`。

## 用法

### GIF

**点一下就同时完成「选中」和「进入逐帧」**，不需要点两下。进入后 GIF 继续播放（不自动暂停），想定格再点暂停。

画面上方浮出控制条（悬停或选中时显形）：

- `◀` 上一帧
- `▶` / `⏸` 播放或暂停
- `▶`（右） 下一帧
- `12 / 48` 当前帧 / 总帧数
- `×` 退出逐帧模式，恢复原来的 GIF

控制条是浮层，贴在画面顶部，**不额外占一行**，平时半透明隐藏、悬停才显形。图标是单色 SVG（跟随文字颜色），整体只用中性灰，没有任何彩色。

控制条或画布获得焦点时，也支持键盘：

- `←` 上一帧
- `→` 下一帧
- `空格` 播放暂停
- `Delete` / `Backspace` 移除这条嵌入
- `Esc` 取消选中

同一时刻只允许一个 GIF 进入逐帧模式（避免多个解码器同时占内存），点开第二个会自动关掉第一个。

### 视频

**倍速条平时不出现，鼠标移到视频上才浮出**（在画面右上角内部）；移开就隐藏，也不会因为选中而一直挂着。

- 下拉里是 0.1 / 0.25 / 0.5 / 0.75 / 1 / 1.25 / 1.5 / 2 / 2.5 / 3
- 选择后立即生效，不需要点播放
- 点击视频画面本身即选中（蓝色描边），不用去点那行 `![[xxx.mp4]]`
- 右侧循环按钮：**默认开启**，亮一点的圆环表示开，暗一点表示关；每个视频可以单独切换

### 取消选中

选中图片 / GIF / 视频后，下面任一操作都能取消选中：

- 点一下页面空白处（正文、侧边栏都行）
- 按 `Esc`
- 焦点移到别的地方

点在被选中的元素自身（包括逐帧控制条、倍速条）上不会取消。

### 选中后删除

点击图片 / GIF / 视频可以选中它（蓝色描边），然后：

- `Delete` 移除这条嵌入，并且**如果这一行只有这一条嵌入，连整行一起删**，不留空行
- `Backspace` 只移除嵌入本身，保留空行
- `Esc` 取消选中

GIF 只有一次点击：选中和进入逐帧同时发生，进去后直接按 `Delete` 就行，不用再点一次。

**这里只改正文，不删文件、也不进回收站。** 想删磁盘上的文件，去文件浏览器里删。

`![[clip.mp4]]`、`![[目录/clip.mp4]]`、`![[a.png|300]]`、`![](path)` 这几种写法都能正确识别并移除。同一段文字里有多条相同的嵌入时，删的是**最靠近光标**的那一条。

## 设置

| 项 | 说明 |
|---|---|
| 启用插件 | 总开关 |
| GIF 逐帧 | 关闭后点击 GIF 不再响应 |
| 视频倍速 | 关闭后不注入倍速选择器 |
| 倍速选项 | 英文逗号分隔，超出 0.1–3 的值会被忽略 |
| 默认倍速 | 新视频的初始倍速，超范围会被钳制 |
| 默认循环播放 | 视频默认循环（默认开启），改完立即作用到已渲染的视频上 |
| GIF 最大帧数 | 超过则跳过逐帧（默认 400），避免长动画卡死 |
| GIF 最大体积（MB） | 超过则跳过逐帧（默认 80） |
| 方向键与 Delete 删除 | 关闭后点选媒体不再响应 Delete |

## 实现说明

**GIF 全程不改动磁盘文件。** 解码只发生在内存里：

```js
const decoder = new ImageDecoder({ data: buffer, type: 'image/gif' });
const frame = await decoder.decode({ frameIndex: n });
ctx.drawImage(frame.image, 0, 0);
```

用的是 Chromium 内置的 `ImageDecoder`，不依赖任何第三方库。画布只是显示层，库里的 `.gif` 文件本身格式、内容、体积都不变，用别的软件照样能打开。

**视频不改动文件**，只是设置 `<video>` 元素的 `playbackRate` 属性。

**删除嵌入不用链接文本拼正则。** 正文里可能写 `![[clip.mp4]]`（最短路径），而 DOM 里的元素只能给出完整路径；两者对不上就会报「正文里没找到这条嵌入」。现在的做法是三层匹配，逐层放宽：

1. 正文里的链接用 `metadataCache.getFirstLinkpathDest` 能解析到同一个文件
2. 链接文本与元素的 `alt` / `src` 原样相等（最贴近用户实际写法）
3. 文件名在正文里唯一

这样最短路径、带目录、带尺寸、markdown 四种写法都能命中；同名文件靠第 2 层精确区分。

**逐帧模式下仍可选中和删除：** 进入逐帧后原 `<img>` 会被隐藏，所以选中和 `Delete` 的监听挂在新的 canvas/浮层容器上，并直接记住对应的 `TFile` 和原始链接写法，不再依赖被隐藏的 `img`。

**取消选中用 document 捕获阶段监听：** 媒体自身（含控制条、倍速条）的点击都会 `stopPropagation`，所以 document 上收到的一定是「点在了别处」，直接取消选中即可；卸载插件时会解绑这些监听。

## 已知限制

- GIF 逐帧依赖 `ImageDecoder`，需要较新的 Obsidian（内置 Chromium 94+）。老版本会提示「当前环境不支持」。
- 超过帧数或体积上限的 GIF 不做逐帧，原样播放。
- 只处理正文里的嵌入内容，Canvas 画布里的媒体不处理。
- 同一时间只支持一个 GIF 逐帧，这是有意的内存保护。

## 卸载

设置里关闭开关，或删除插件文件夹。不会影响任何笔记和附件文件。
